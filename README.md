# 录屏 → 成片：全自动怀旧游戏解说流水线

把一条几十分钟的原始游戏录屏，全自动变成一条**可直接发布**的 B 站解说视频：
AI 看片选段 → 写稿（全稿一次成文，段间衔接）→ 克隆你的音色逐句配音 → 声画逐句对齐合成 → 封面/竖屏版/验收图/投稿信息 → 剪映精修草稿。

> 本项目由一条真实发布的解说视频验证。全链路免费自建：GLM-4V 免费视觉模型 + IndexTTS2 本地音色克隆 + ffmpeg，无任何付费 API。

## 它做了什么

```
拖入录屏
   │
   ▼
[10 粗剪]  每10秒抽帧，GLM-4V 逐帧识别：游戏画面/桌面/加载，打精彩度分
   │        → 粗剪时间线.txt（人可读、可手动改）
   ▼
[20 细剪]  AI 决定叙事结构（开场钩子=全片最高分瞬间 + 25-60秒正片段）
   │        段内 4 秒精抽帧细看 → 全稿一次成文（一条叙事线、段间衔接、反流水账）
   │        → 每句解说锚定到画面时间点（句级声画对齐的原料）
   │        → 生成 投稿信息.txt（标题候选/简介/标签）
   ▼
[01 配音]  IndexTTS2 克隆你的音色，逐句合成（每句真实时长 → 帧级字幕对齐）
   ▼
[03 剪辑]  配音驱动合成：
   │        · 句级锚定：讲到哪句，画面就是那句描述的事件（逐句切片变速）
   │        · 字幕直出零错字、BGM 自动垫底跨段连续、原声压混、限幅防爆音
   │        · 老素材画中画（细剪阶段 AI 按需爬图 + 视觉验证相关性）
   ▼
[30-33]    封面（GLM 看图写标题，保证图文一致）/ 竖屏 9:16 / 九宫格验收图 / 剪映草稿
```

## 快速开始

### 0. 依赖

| 依赖 | 用途 | 获取 |
|---|---|---|
| ffmpeg（PATH 里可用） | 全部音视频处理 | `winget install Gyan.FFmpeg` |
| Python 3.10+ | 脚本 | [IndexTTS2 的 venv 即可复用](https://github.com/index-tts/index-tts) |
| IndexTTS2 | 本地音色克隆（含模型权重） | 按其官方仓库安装 |
| 智谱 API Key | 视觉理解（glm-4v-flash 免费） | https://open.bigmodel.cn |

### 1. 安装

```bat
git clone https://github.com/alonesanewolf/ai-video-pipeline.git
cd ai-video-pipeline
copy glm_key.example.txt glm_key.txt   ← 粘贴你的智谱 Key
pip install imageio psutil             ← 33 剪映草稿需要
```

### 2. 配置（可选，有默认值）

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `AVP_WORK` | `D:\stream-tools\workflow` | 工作目录（中间产物和成片都在这） |
| `AVP_TTS_ROOT` | `D:\stream-tools\IndexTTS2` | IndexTTS2 安装目录（含 checkpoints） |
| `AVP_VOICE` | `D:\stream-tools\my-videos\voice_sample.mp3` | 音色样本（10-20 秒干净人声） |
| `AVP_VECTCUT` | `D:\stream-tools\VectCutAPI` | （可选）VectCutAPI 克隆目录，剪映草稿用 |

目录结构和上面不一样的话，设置环境变量即可，代码不用改。

### 3. 跑

**方式一**：把录屏视频文件拖到 `全自动成片.bat` 图标上。
**方式二**：手动逐步跑 `10_粗剪 → 20_细剪 → 01_配音 → 03_剪辑 → 30/31/32/33`。
（`00_看片.py` 是独立工具：快速 AI 看片，不进主流程。）

粗剪结果有缓存：想保留 AI 选段只改文案，删 `粗剪.json` 之外什么都不用动；想全部重扫就删掉它。

### 4. 产出

| 文件 | 说明 |
|---|---|
| `成片.mp4` | 横屏成片（声画逐句对齐 + 字幕 + BGM） |
| `竖屏版.mp4` | 1080×1920，抖音/视频号直传 |
| `cover.jpg` | 封面（AI 看图写标题，图文一致） |
| `验收图.jpg` | 九宫格抽帧 + 音量报告，发布前 10 秒人工把关 |
| `投稿信息.txt` | 标题候选 / 简介 / 标签 / 话题 |
| `剪映草稿` | 画面/解说/字幕/BGM 四轨时间线，打开剪映即可可视化精修 |

## 设计取舍（为什么这样做）

- **全稿一次成文，不逐段独立写**——逐段写出来的稿子段与段互不认识，没有叙事逻辑。一次写整条才可能有起承转合和段间衔接。
- **句级画面锚定**——段级对齐只保证"这段解说配这段画面"，整段变速后句子和画面瞬间会漂移。写稿后让 AI 把每句解说匹配到精抽帧的时间点，合成时画面按句切片变速。
- **文案层规避 TTS 弱项**——数字写汉字、禁英文 ID、多逗号停顿；写稿时套话黑名单前置 + 出现自动重写双保险。
- **素材按需找，不预先囤**——每段写完稿才知道需要什么图，AI 出关键词 → 爬图 → GLM 视觉验证相关性（不合格宁缺毋滥）。
- **人机分工**：AI 干粗活，关键决策（粗剪时间线、解说稿）落成文本给你过目改完再继续。
